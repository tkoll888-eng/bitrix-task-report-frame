# Дизайн: отчет по задачам во вкладке смарт-процесса

## Цель

Создать новый VibeCode/Bitrix24 проект с нуля в `C:\AI\tasks`.
Приложение добавляет дополнительную вкладку/frame в карточку элемента смарт-процесса и показывает отчет по задачам, привязанным к текущему элементу.

Первый релиз делаем сфокусированным:

- Показываем только задачи, привязанные к текущему элементу смарт-процесса.
- Добавляем фильтры отчета.
- Показываем общий подсчет планируемых трудозатрат и затраченного времени.
- Добавляем HTML-версию для печати.
- После реализации деплоим приложение на VibeCode.

В первый релиз не входят PDF, Excel и отчеты по всем задачам портала.

## Размещение

Приложение отображается в карточке элемента смарт-процесса как дополнительная вкладка/frame рядом с данными элемента.

В режиме Bitrix24 frame приложение получает контекст текущего элемента из placement:

- `entityTypeId`
- `itemId`

В локальном режиме контекста Bitrix24 нет. Поэтому для локальной проверки пользователь вручную передает ID элемента через URL:

```text
http://localhost:<port>/?entityTypeId=184&itemId=123
```

Если параметры не указаны, приложение показывает подсказку:

```text
Для локальной проверки добавьте в URL параметры entityTypeId и itemId, например ?entityTypeId=184&itemId=123.
```

## Шапка отчета

В шапке отчета показываем:

- `Отчет по задачам`
- Автоматическое название отчета компании:
  - `Отчет по сопровождению <Компания>`, если компания указана.
  - `Отчет по сопровождению`, если компания не указана.
- `Объект: <название элемента смарт-процесса>`
- `Компания: <название компании>` или `Компания: не указана`
- `Период: <выбранный период фильтра>`
- Кнопка `Печать`

## Колонки

Таблица содержит колонки:

- `Дата создания`
- `Статус`
- `Название`
- `Планируемые трудозатраты`
- `Затраченное время`
- `Дата завершения`
- `Крайний срок`
- `Наименование позиции`
- `Теги`

`Название` задачи обязательно делаем кликабельной ссылкой на задачу в Bitrix24. При открытии ссылки пользователь должен попадать в карточку задачи.

`Наименование позиции` берем из пользовательского поля задачи с видимым названием `Наименование позиции`.
Технический код поля пока неизвестен. На этапе реализации его нужно найти через API полей задач или указать в конфигурации, когда вы его дадите.

## Фильтры

Панель фильтров содержит:

- `Отчет за период`
- `Теги содержит`
- `Дата завершения`
- `Статус`
- `Применить`
- `Сбросить`

### Отчет за период

`Отчет за период` фильтрует по активности задачи.
Задача попадает в отчет, если она была создана или изменена внутри выбранного периода:

```text
Дата создания внутри периода ИЛИ дата изменения внутри периода
```

Период по умолчанию: текущий календарный месяц.

### Теги

`Теги содержит` ищет задачи, у которых хотя бы один тег содержит введенный текст.

### Дата завершения

Фильтр `Дата завершения` поддерживает:

- `Сегодня`
- `Неделя`
- `Месяц`
- Ручной диапазон дат

### Статус

Фильтр `Статус` работает как мультивыбор. Пользователь может выбрать один или несколько статусов одновременно, как в интерфейсе Bitrix24.

Фильтр показывает статусы как в интерфейсе Bitrix24, например:

- `Новая`
- `В работе`
- `Ждет контроля`
- `Завершена`
- `Отложена`

Внутри приложения эти названия мапятся на технические значения статусов для API. Если выбрано несколько статусов, отчет показывает задачи, подходящие под любой из выбранных статусов.

## Итоги

Под основной таблицей показываем блок `Всего`.

Итоги считаются по текущей отфильтрованной выборке:

- Сумма `Планируемые трудозатраты`
- Сумма `Затраченное время`

Время показываем в формате `H:MM`.

## Печатная форма

Кнопка `Печать` открывает HTML-версию отчета с текущими примененными фильтрами.

Печатная форма содержит:

- Автоматическое название отчета компании.
- Название объекта.
- Название компании.
- Выбранный период отчета.
- Таблицу задач.
- Итоги по планируемым трудозатратам и затраченному времени.

Для печати используем отдельные CSS-стили:

- Скрываем кнопки и интерактивные фильтры.
- Делаем таблицу читаемой на бумаге.
- Сохраняем шапку отчета и блок итогов.

В первом релизе используется только HTML-печать. PDF не входит в объем первого релиза.

## Поток данных

1. Frame открывается внутри карточки элемента смарт-процесса.
2. Frontend читает placement context.
3. Если placement context недоступен, frontend читает `entityTypeId` и `itemId` из URL для локальной разработки.
4. Frontend отправляет контекст и фильтры на backend.
5. Backend загружает элемент смарт-процесса, чтобы получить название объекта и компанию.
6. Backend загружает задачи, привязанные к текущему элементу смарт-процесса.
7. Backend применяет фильтры, нормализует поля, мапит статусы и считает итоги.
8. Frontend показывает таблицу и итоги.
9. Печатная форма запрашивает те же отфильтрованные данные и рисует HTML-страницу для печати.

## Ошибки

Если задач нет, показываем:

```text
По выбранным фильтрам задач не найдено.
```

Если в режиме Bitrix24 frame не удалось определить текущий элемент смарт-процесса, показываем:

```text
Не удалось определить текущий элемент смарт-процесса.
```

Если в локальном режиме не удалось определить элемент, показываем подсказку из раздела `Размещение` про параметры `entityTypeId` и `itemId`.

Если пользовательское поле задачи `Наименование позиции` не найдено, отчет все равно работает. Колонка остается пустой, а backend пишет предупреждение в лог.

Если компания не указана в элементе смарт-процесса, отчет все равно строится и показывает:

```text
Компания: не указана
```

## Проверка

Перед деплоем:

- Открыть приложение локально с параметрами `entityTypeId` и `itemId`.
- Проверить, что показываются только задачи выбранного элемента смарт-процесса.
- Проверить, что период по умолчанию равен текущему календарному месяцу.
- Проверить фильтр `Теги содержит`.
- Проверить быстрые фильтры и ручной диапазон для `Дата завершения`.
- Проверить, что статусы отображаются как в интерфейсе Bitrix24.
- Проверить, что можно выбрать несколько статусов одновременно.
- Проверить итоги по планируемым трудозатратам и затраченному времени.
- Проверить `Наименование позиции`, когда будет известен код пользовательского поля.
- Проверить HTML-версию печати с теми же примененными фильтрами.

После деплоя:

- Проверить, что приложение открывается как вкладка/frame в карточке элемента смарт-процесса.
- Проверить, что placement context определяется автоматически.
- Проверить, что шапка отчета показывает объект, компанию, период и автоматическое название отчета компании.
- Проверить, что печатная форма открывается из frame.

## Открытая деталь реализации

На этапе реализации приложение должно либо найти его через API полей задач, либо взять из конфигурации, если вы дадите код поля.
