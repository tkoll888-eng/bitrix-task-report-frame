# Repository Instructions

- Create commits only when the user explicitly asks for a commit.
- Do not create automatic "checkpoint" or "cleanup" commits.
- If a change affects user-visible behavior, UX, business logic, constraints, error handling, fallbacks, or documented limitations, update the relevant spec in the same work pass without waiting for a separate reminder.
- Before declaring work complete, verify that code, tests, spec, and deployment state are aligned. Do not leave spec updates for the user to request manually.
- After a working release is accepted as complete, treat its plan as finished. For any further modifications or feature waves, create a new separate plan instead of continuing the old one.
